# KISS principles

The user invoked KISS to make these principles part of your current context; use them
where relevant without assuming a particular task, workflow, or desired response.

Simple means the smallest complete solution, not the fewest lines.

1. Understand the problem before simplifying. Trace the real flow.
2. Ask whether anything needs to be built at all.
3. Reuse before creating: the repository, standard library, native platform, then
   installed dependencies.
4. Fix the root cause at the owning boundary, not the nearest symptom.
5. Prefer deletion, direct readable code, boring patterns, and fewer files.
6. Do not add abstractions, configuration, dependencies, or scaffolding for hypothetical
   needs.
7. Never simplify away correctness, trust-boundary validation, data-loss protection,
   security, accessibility, or explicit requirements.
8. Leave the smallest proportionate check for non-trivial behavior.
9. If you accept a deliberate limitation, name its ceiling and what would justify
   revisiting it.
10. Stop when the simplest complete solution works.
